# 编辑器工作台: 风格与自由布局提案

状态: **待用户确认, 尚未实现**。更新: 2026-10-15。

本次只提交此前的功能改动并整理设计, 不直接替换现有 UI。
另有独立的 [UI 预览 bin](EDITOR_UI_PREVIEW.md)供确认风格和布局, 不代表正式编辑器已迁移。
操作规则见 [交互方案](EDITOR_INTERACTION_SPEC.md); 现有功能状态仍以
[键盘操作](EDITOR_KEYBOARD.md)、[Autoplay](EDITOR_AUTOPLAY.md)、
[设置](EDITOR_SETTINGS.md)为准。本文不是当前使用说明。

## 1. 设计方向

根据预览反馈, 方向调整为 **炭灰半透明工作台 + 悬浮工具条 + 单编辑器分屏**。
从 Blender 借鉴区域拆分、编辑器类型切换和工作区; 从 VS Code 借鉴
紧凑信息密度、命令搜索和明确的焦点。保留谱面工具自己的 note 贴图与空间语言。
每个区域只显示一个编辑器, 不使用标签组或在区域内切换 Tab。

已确认的视觉约束: 左侧工具条在画布内悬浮; 顶部使用不偏色的炭灰半透明材质, 不用纯黑;
按钮小而扁平, 没有与背景明显隔离的常驻色块和描边。独立预览已按此更新,
全局工具合并为一行, 每个分区的工具也并入标题行, 但正式编辑器仍未迁移。

需要改善的不是单纯的配色, 而是工作区层级、信息密度、操作对象和反馈:

- 主要时间轴获得最多空间, Pad、属性、模板是可重新安排的独立区域。
- 页面采用连续工作表面和细分隔线, 不把每个设置或区块装进浮动卡片。
- 高频操作靠近编辑内容, 低频配置进入设置; 不把全部功能堆进顶栏。
- 面板标题、当前对象、当前编辑层级清楚, 但不挤占画布。
- 布局变化不改变音符大小, 不触发 seek, 不重置判定或重建核心。
- 任何布局操作都能恢复, 键盘操作不依赖鼠标恰好悬停在哪个区域。

### 风格候选

| 方向 | 表现 | 取舍 |
| --- | --- | --- |
| A. 炭灰 + 半透明, 当前方向 | 深灰顶栏、菜单与悬浮工具条, 极弱亮边; 内容面不透明 | 轻量透明绘制, 磨砂后置 |
| B. 同色实底, 可访问性备选 | 保持相同尺寸与层级, 关闭透明 | 长时间编辑或降低透明效果时使用 |
| C. 真实磨砂, 后续可选 | 在 A 的局部浮层增加背景模糊 | 需先验证性能, 不默认扩大透明面积 |

当前 A 采用紧凑、扁平的控件。不是整页透明, 也不引入
装饰性渐变、发光、背景光斑或大圆角。以下数值是初始设计参数, 需样稿确认。

## 2. 视觉规范草案

### 表面与语义色

| Token | 初始值 | 用途 |
| --- | --- | --- |
| Window | `#1E1F20` | 窗口底色 |
| Canvas | `#232425` | 谱面与事件时间轴底色 |
| Panel | `#262728` | 不透明辅助表面 |
| Glass | `#232425`, 约 82% 不透明度 | 顶栏、菜单与悬浮工具条 |
| Control | `#303132` | 需要底色的输入控件, 不用于普通按钮 |
| Border | `#3E3F40` | 网格强线、必要分隔; 不用于普通按钮描边 |
| Text | `#E3E6E8` | 主文字 |
| TextSecondary | `#ACB2B8` | 次级数值、标签 |
| Selection | `#79B8F4` | 选中轮廓、键盘焦点 |
| EditCursor | `#E5C37A` | 编辑光标, 与播放线区分 |
| Playback | `#F16D7A` | 红色播放线 |
| ActiveInput | `#6BC8AF` | 正在生效的触摸区间 |

底色不偏蓝、不偏棕。强调色只标识状态, 不把整个面板染色。
Note 继续使用项目自己的贴图; EACH、Break 等颜色含义不被主题替换。
选中、焦点、悬停分别用实线、标题标记、细轮廓区分, 不能仅靠颜色。

### 磨砂的边界

- 半透明使用位置: 顶栏、区域工具条、菜单、命令搜索、临时属性浮层、悬浮工具条。
- 不使用位置: note 网格、波形、Autoplay 事件区、常驻属性数值区、Pad 判定内容。
- 当前预览材质: 约 82% 炭灰底色, 仅浮层外缘使用极弱亮边; 无实时背景模糊。
  不采用纯黑, 也不用浅灰色块或明显边框制造材质感。
- 文字、图标、手柄始终不透明; 不让细网格透到文字下面。
- 模糊只处理应用内部背景, 不默认读取桌面或依赖 macOS 特有材质。
- 设置提供“实色 / 半透明 / 磨砂”和“减少透明效果”; 高对比模式使用实色。
- 未完成渲染方案验证前, 不承诺实时磨砂没有性能成本。先保证播放与输入响应。
- 降级为实色时尺寸、颜色语义、布局完全不变。

### 尺寸与控件

- 默认正文 13 逻辑点, 菜单/面板标题 12, 次级数值 11; 不随窗口宽度缩放字号。
- 紧凑控件高 22-24, 图标 14-15, note 工具命中区 26, 贴图 20。
- 菜单/工作区/播放共用一行约 28 高的全局顶栏; 区域标题与工具共用一行 26 高, 状态条约 20。
- 宽度不足时工作区切换折叠为菜单, 次要播放控制进入 Playback, 区域工具进入溢出菜单; 不换行。
- 普通按钮默认透明无描边, 悬停/按下只叠加微弱亮度; 选中状态靠图标色和细标记。
  不让 File/Edit、缩放、播放等按钮各自形成有边框的方块。
- 分隔线视觉宽 1, 可拖动命中带 6-8; 小手柄的命中区大于视觉尺寸。
- 停靠面板直角相接; 控件圆角 3-4, 菜单与浮层圆角 6-8。
- 文字字距为 0; 时间和数值使用等宽数字, 标签与数值两列对齐。
- 按钮优先使用一致的图标资源; 工具类型使用 note 贴图, 不用字母代替。
- 二选一状态用切换开关, 模式用分段控件, 选项用菜单, 数值用可键入的步进框。
- 图标提供悬停提示和可访问名称; 不在画布写教学说明或堆快捷键提示。
- UI 缩放、谱面 note 尺寸、Pad 内容缩放、时间轴时间倍率是四个独立设置。

## 3. 工作台结构

全局区域只有两个: 合并菜单/工作区/播放控制的单行顶栏, 以及底部状态栏。
中间所有内容是可组合区域, 不是写死的“左栏/右栏/底栏”。
每个区域只有一行“类型/标题 + 局部工具 + 布局动作”, 不另设第二条工具栏。

### 可放入区域的编辑器

| 编辑器类型 | 内容 |
| --- | --- |
| 谱面 | 纵向或横向 note 时间轴, 每个视图独立倍率与滚动 |
| Pad | 当前全局播放时刻的实时预览, 可显示判定覆盖层 |
| Autoplay | 少量复用轨道及按需展开的传感器事件 |
| 属性 | 活跃对象的属性, 可固定到指定对象 |
| 资源/场景 | 文件、难度、模板库、模板实例; 按编辑器类型单独显示 |
| 历史 | 可读的已确认编辑动作和撤销位置 |
| 总览/波形 | 全曲定位、循环范围和音频波形 |

### 区域操作

1. 拖分隔线调整大小, 不更改字体或 note 大小。
2. 每个分屏严格只有一个编辑器, 标题左侧的类型菜单直接替换该区域, 不增加标签。
3. 面板菜单提供左右/上下拆分、切换编辑器类型、移动、交换区域、关闭。
4. 关闭区域时收拢对应分屏, 不删除编辑对象; 最后一个区域不可关闭。
5. 双击标题条空白处或点击最大化图标临时最大化; 再次操作恢复原布局。
6. 可复制同一谱面视图, 一边看全局一边看细节; 数据同步, 视图倍率独立。
7. 布局菜单提供保存、另存、重命名、恢复预设及单独的“撤销布局更改”。
8. 可锁定区域结构, 仍允许调整分隔比例、编辑内容与滚动, 禁止拆分/交换/关闭/类型替换。

角落拖拽拆分可以作为后续熟练操作, 不能是唯一入口。
第一阶段支持窗内拆分、区域交换和区域类型替换; 不引入多标签容器。
独立预览通过标题右侧菜单提供拆分/交换/关闭, View 菜单添加独立分屏。
窗内悬浮编辑区域为第二阶段, 与画布内的小型悬浮工具条不同。
真正脱离主窗口、多显示器原生窗口需要单独验证, 不能用窗内悬浮冒充已支持。

### 焦点、状态与持久化

- 点击或 F6 选择活动区域; 单纯移动鼠标不夺取键盘焦点。
- 面板类型切换保留对应视图状态; 关闭面板不删除谱面对象。
- 同一文档共享数据、历史、播放时钟和核心会话; 同类型视图共享对象选择。
- 谱面 note 选择与 Autoplay 事件选择分开, 属性默认跟随最后活跃编辑器。
- 属性可固定对象; 固定对象被删后显示失效状态, 不跳到另一个对象上继续编辑。
- 工作区切换只改变布局与视图状态, 不重建核心、重新载谱面或重启音乐。
- 未确认草稿不因切换布局被悄悄提交或丢弃; 跨编辑作用域前明确确认/取消。
- 布局保存到用户偏好, 不进入谱面 JSON, 不使谱面出现未保存标记。
- 保存分屏比例、区域类型、区域位置、可见状态和各视图参数; 使用版本化格式。
- 窗口变小优先最大化主要编辑器或收起次要区域, 不缩小字体或自动合并为标签。
- 损坏或不兼容的布局可回退到预设, 保留原配置备份。

## 4. 默认布局提案

这是默认入口, 不是功能限制。所有预设都能改成自己的布局。

### A. 谱面编辑, 推荐默认

```text
文件 编辑 视图 播放 | 谱面 Autoplay 联合 | 播放 时间 循环 速度 | 布局 设置
+---------------------------------------------+----------------------+
| 谱面: 纵向/横向  工具  吸附  细分  缩放      | Pad 预览             |
|                                             |                      |
|                 note 时间轴                 |                      |
|                                             +----------------------+
|                                             | 属性                 |
|                                             |                      |
+---------------------------------------------+----------------------+
| 总览 / 波形 / 循环范围                                              |
+--------------------------------------------------------------------+
保存状态 / 核心同步状态 / 所选数量 / 时值与 lane
```

- 标准窗口约 68% 宽给谱面、32% 给右侧, 右侧上下约 55:45。
- 模板/历史从区域类型菜单进入, 或拆成独立区域; 左侧 note 工具条浮在谱面画布内,
  只占工具实际内容高度, 不使用贯穿画布的侧栏底色。
- 总览初始 56-72 高, 可以折叠为细条。
- 宽屏可把右下属性拆到最右列, Pad 单独放中间; 不强制自动变成三栏。
- 对比当前左右近似等宽分配, 主要增益是完整的谱面编辑空间和可调整的右侧。

### B. Autoplay 精修

```text
+---------------------------+----------------------------------------+
| Pad 预览                  | 属性 / 当前 note 与事件归属            |
+---------------------------+----------------------------------------+
| Autoplay: 选择/绘制   吸附   细分   缩放   跟随                     |
| 标尺 / 循环范围                                                    |
| 轨道 1   [Tap]     [Slide................]             [Touch]      |
| 轨道 2             [Hold...........]                              |
| 轨道 3                                                            |
| 轨道 4                                                            |
| 选中片段展开: B1 [======]  C [=======]  B5 [=====]                  |
+--------------------------------------------------------------------+
```

- 下方轨道区默认约 60%-65% 高, 保留四条复用轨道。
- 精修展开实际需要的传感器行, 不为每个 note 永久创建一行。
- Note、同头 slide、连接段的归属不因片段折叠或轨道排布改变。

### C. 联合检查

上半部分“谱面 + Pad”, 下半部分 Autoplay; 属性通过替换区域或额外分屏进入。
同一红线与 note ID 联动, 不使用两套互相漂移的播放时钟。用于边改谱面边检查输入。

### 小窗口与最小尺寸

- 以 1440x900、1280x720、1920x1080 逻辑尺寸检查默认布局。
- 谱面区域建议最小宽 360、高 300; 属性建议最小宽 240; Pad 建议至少 240 方形。
- 不满足最小尺寸时先收起资源、总览和属性区域, 必要时切单区域工作模式。
- 触摸设备使用舒适密度, 不把桌面密集布局整体等比压缩。
- 窗口调整后重新计算视口锚点, 保持正在编辑的内容可见; 不改全局时间。

## 5. 顶栏、属性与设置

### 信息归属

| 位置 | 应包含 | 不应包含 |
| --- | --- | --- |
| 全局顶栏 | 文件、编辑、视图、播放菜单、工作区、布局与设置 | 全部 note 属性的常驻按钮 |
| 顶栏内的播放控制组 | 播放/暂停、位置、循环、速度; 次要项进入播放菜单 | 每条事件的动作和区域, 第二条播放栏 |
| 面板标题行 | 标题、工具、吸附、细分、朝向、局部缩放; 窄屏时使用工具菜单 | 音效与核心调试参数, 第二条工具栏 |
| 属性 | 所选对象的可编辑值与只读归属 | 长篇说明、全局偏好 |
| 设置 | 外观、布局默认值、输入、音频、预览与核心 | 当前 note 的时间/lane |
| 状态栏 | 保存失败/同步中/未保存、焦点对象、选择数 | 反复滚动的教学提示 |

### 设置界面

采用可调整大小的单一设置窗口: 左侧类别、中间搜索与设置列表, 不层层弹窗。
类别为外观、工作区、输入与快捷键、时间轴、Pad 与判定、音频、Autoplay/核心、文件。
每个值显示作用范围: 当前视图、工作区或全局默认; 同一个开关只有一份状态。

UI 偏好即时生效并保存; 改动判定/播放参数采用明确的应用动作, 不在拖滑杆每一帧
重建核心。失败保留旧有效值并允许重试。快捷键设置检测冲突并提供恢复默认。

## 6. 实施边界与确认节点

| 阶段 | 内容 | 进入条件 |
| --- | --- | --- |
| D0 | 操作与布局文档, 收集风格反馈 | 本次 |
| D1 | 谱面/Autoplay 两张视觉样稿, 含磨砂菜单与焦点状态 | 确认下方方向 |
| P0 | 主题、尺寸、全局播放条、属性层级, 保留原功能 | 样稿确认 |
| P1 | 自由拆分/停靠/类型切换、工作区保存与恢复 | P0 可用 |
| P2 | 谱面直接操作、Autoplay 区间编辑、统一命令与焦点 | 操作方案确认 |
| P3 | 局部真实模糊、窗内悬浮、多窗口可行性验证 | 交互稳定且性能允许 |

实现前先确定可替换的区域容器边界, P0 不再新增写死的左右面板比例。
P1 依然沿用现有 egui/macroquad, 不因为改界面就迁移整套技术栈。
Blur 先用实色占位并保留同样层次, 后接渲染方案; 不把 CSS 的模糊效果当成原生
渲染器现成能力。多个 Pad 视图不能重复推进核心或重复播放音频。

每阶段只做相关编译/最小检查, 主要体验交给用户试用, 不默认扩展成大规模测试工程。

## 7. 参考与实现入口

官方参考只用于布局与可读性原则, 不要求逐像素复制其视觉或快捷键:

- [Blender Areas](https://docs.blender.org/manual/en/3.3/interface/window_system/areas.html): 区域拆分、合并与编辑器组织。
- [VS Code Custom Layout](https://code.visualstudio.com/docs/configure/custom-layout): 标签分组、停靠、布局恢复与键盘移动视图。
- [Apple Sufficient Contrast](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/sufficient-contrast-evaluation-criteria/): 透明背景也需要验证文字、图标与状态对比度, 提供减少透明效果。

现有实现入口:

- `editor/src/theme.rs`: 样式 token。
- `editor/src/ui/layout.rs`, `editor/src/ui/mod.rs`: 当前固定区域布局。
- `editor/src/ui/toolbar.rs`, `editor/src/ui/inspector.rs`: 全局入口与属性。
